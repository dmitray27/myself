Оценка по коду (UART 115200 ≈ 11,5 КБ/с, ~87 мкс/байт; замеров на железе не делал):

**RX (критично для I2S):** DMA-буфер 16×256 кадров @48 кГц ≈ 85 мс запаса. На каждый 50-байтный блок печатается ~300 байт ≈ 25 мс блокировки, а сам блок в эфире 2,5 с + пауза 500 мс → ~1% времени, в буфер укладывается с запасом. Лог преамбулы — ~45 байт раз в ~300 мс (≈4 мс), `[LEVEL]` раз в 5 с. Опасным был только вывод полного сообщения (до 8 КБ ≈ 700 мс > 85 мс → потеря блоков), он уже убран. Т.е. сейчас RX логи не тормозят приём; `AFSK_VERBOSE 0` даст ~1% и пару мс стабильности на блок.

**TX:** `ESP_LOGI` с текстом каждого блока (~100 байт ≈ 9 мс) в tx_task — вне битового цикла, на эфир не влияет.

**Wi-Fi:** `ESP_LOGI("WS text from fd …")` печатает весь кадр (до 1 КБ ≈ 90 мс) в httpd-таске — это единственное место, где лог заметно тормозит: задержка ответа/эха на ~0,1 с на длинном сообщении и блокировка других WS-клиентов на это время. Стоит обрезать до длины или перевести в `ESP_LOGD`.

**Flutter:** ~30 `debugPrint` — микросекунды, незаметно.

Итого: реального замедления ~1% на RX и до ~0,1 с на длинный WS-кадр. Убрать/обрезать WS-лог в той же ветке?

Причина найдена — в манифесте у MainActivity стоит `android:taskAffinity=""` вместе с `launchMode="singleTop"` (<ref_snippet file="/home/ubuntu/repos/myself/flutter_info/android/app/src/main/AndroidManifest.xml" lines="20-21" />). Когда вы открываете приложение по тапу на уведомление сервиса, Android запускает Activity как новую задачу (PendingIntent из сервиса всегда с NEW_TASK); с пустой affinity система не находит «свою» задачу, а `singleTop` переиспользует Activity только внутри той же задачи — получается второй экземпляр. Возможные последствия: два Flutter-движка, два WebSocket-подключения к плате, дублирование сообщений, «Выйти» закрывает только одну копию. Это давно в `core` (коммит 7852e1f), не от последних правок.

Исправление — две строки, обе копии:
```xml
android:launchMode="singleTask"
<!-- taskAffinity="" убрать -->
```
`singleTask` = одна задача на приложение; тап по уведомлению просто поднимает существующее окно.

За: убирает дубли и все следствия; стандартная настройка для приложений с постоянным уведомлением. Против/риски: (1) при `singleTask` система при возврате из уведомления вызывает `onNewIntent`, а не создаёт Activity — Flutter это штатно поддерживает; (2) если `taskAffinity=""` ставили намеренно (защита от task hijacking или чтобы окно не «прилипало» к другому приложению) — этот эффект пропадёт; в git причина не записана. Проверка на телефоне после сборки: открыть приложение, свернуть, тапнуть по уведомлению → в недавних должна быть одна карточка.

3. **WebSocket** `ws://192.168.4.1/ws`, текстовые кадры: клиент шлёт `setName:<имя>`, `msg:<имя>:<id>:<текст>` (или legacy без id); плата транслирует `<имя>:<id>:<текст>`, `System:<текст>`, `ping`/`pong`, до 20 сообщений истории при подключении. Разбор — `chat_protocol.dart`, тесты `chat_protocol_test.dart` зеркалят `name_is_valid` и лимит размера `from:id:text` из прошивки.
4. **Лимиты**: длина имени/сообщения и интервал между кадрами (`WS_MIN_MSG_INTERVAL_MS`, ≥100 мс после `setName`) — приложение проверяет их до отправки, поэтому при изменении констант в `afsk_common.h`/`wifi_link.c` нужно править и Dart.

Чего приложение **не** знает: AFSK (скорость, преамбула, 3-байтный заголовок блоков, CRC), номера портов ttyUSB, версия ESP-IDF, тип чипа (esp32/esp32s3). Т.е. прошивку можно менять свободно, пока не трогаете пп. 1–4; и наоборот — Flutter-версии совместимы с любой прошивкой, отдающей этот же WS/HTTP-контракт (старые кадры без id тоже принимаются). Версионирования протокола нет — при несовместимом изменении приложение просто получит непонятные кадры, без внятной ошибки; если планируете менять протокол, стоит добавить `version` в `/ping`.

**12. Виджет / плитка «быстрая фраза» на Android**

Два варианта:
- *Виджет на домашнем экране* (`AppWidgetProvider` в Kotlin, пакет `home_widget` во Flutter): кнопки «Принял», «SOS», «Позиция» прямо на рабочем столе. По нажатию — `Intent` в `ChatForegroundService`, который отправляет кадр по уже открытому WebSocket (приложение при этом не открывается). Если сервис не запущен (пользователь нажал «Выйти») — виджет открывает приложение и после подключения дошлёт фразу.
- *Плитка в шторке быстрых настроек* (`TileService`, Android 7+): одна плитка = одна фраза (обычно SOS), доступна с экрана блокировки при разрешении.

Нюансы: сейчас отправка живёт в Dart (`ChatController`), сервис в Kotlin только держит уведомление; для виджета нужно либо поднимать Dart-движок в фоне (`FlutterEngine` headless — тяжело), либо продублировать в Kotlin минимальный WebSocket-клиент (`OkHttp`, ~80 строк: `setName`, `msg:`, id). Кому полезно: в поле, когда телефон в кармане/на руле и нужно одно нажатие. Оценка: 0.5 сессии, ещё 0.2 на PRO-статусы через уведомление.

packages/radiochat_core/      # dart-пакет: протокол, store, controller, info_dialog, тесты
packages/radiochat_pro/       # PRO-надстройка: статусы, stat, peers, история, AP (зависит от core)

*Devin* · 2026-10-05 13:04 UTC

Подробно про свою функцию счётчика (`buildCounter`) в `TextField`.

**1. Что это такое.** `buildCounter` — параметр `TextField` типа `InputCounterWidgetBuilder`:
```dart
typedef InputCounterWidgetBuilder = Widget? Function(
  BuildContext context, {
  required int currentLength,   // символов сейчас в поле
  required int? maxLength,      // значение maxLength у TextField (может быть null)
  required bool isFocused,      // поле в фокусе или нет
});
```
Это callback-«строитель»: вы не рисуете счётчик сами, а отдаёте Flutter функцию, и он вызывает её при каждой перерисовке поля (ввод, удаление, фокус, смена темы). Вернуть можно любой виджет или `null` — тогда под полем ничего нет (место не резервируется).

**2. Куда попадает результат.** `TextField` внутри оборачивает ввод в `InputDecorator`, у которого есть слот `counter` (правый нижний угол под линией поля, рядом слева — `helperText`/`errorText`). Если `buildCounter` не задан, но есть `maxLength`, Flutter сам кладёт туда `Text('$currentLength/$maxLength')` в стиле `counterStyle` темы. Ваша функция просто подменяет этот виджет. Если задать и `decoration.counterText`, он имеет приоритет — поэтому в нашем коде `counterText` не трогаем.

**3. Как считаются символы.** `currentLength` — это `controller.text.characters.length` (пакет `characters`): «графемы», а не байты и не code units. Эмодзи 👍 = 1, кириллическая буква = 1, хотя в UTF-8 это 4 и 2 байта. Поэтому у нас две независимые проверки: счётчик/`maxLength` ограничивают 300 символов, а `messageFitsFrame` перед отправкой — 1024 байта кадра.

**4. Что делает `maxLength` помимо счётчика.** Он ставит `LengthLimitingTextInputFormatter`: ввод обрезается на лимите (поведение `maxLengthEnforcement`, по умолчанию «обрезать»). Счётчик — только индикация, ограничение работает и без него. Если хотите «можно набрать больше, но подсветить красным» — `maxLengthEnforcement: MaxLengthEnforcement.none` плюс свой счётчик с `currentLength > maxLength`.

**5. Наш текущий код** (<ref_snippet file="/home/ubuntu/repos/myself/flutter_color/lib/screen_pro.dart" lines="576-589" />):
```dart
buildCounter: (context, {required currentLength, required isFocused, maxLength}) {
  if (maxLength == null || currentLength < maxLength - 50) return null; // молчим до последних 50
  return Text('$currentLength/$maxLength', style: const TextStyle(fontSize: 11));
},
```
Логика: в радиочате лимит далеко, и постоянный «12/300» только шум; показываем, когда реально близко.

**6. Варианты, которые стоит попробовать самому:**
- Остаток: `Text('осталось ${maxLength - currentLength}')`.
- Цвет: `color: currentLength >= maxLength - 20 ? Theme.of(context).colorScheme.error : null` — берите цвета из темы, чтобы работало в тёмной и в наших белом/чёрном вариантах.
- Только в фокусе: `if (!isFocused) return null;`.
- Байты вместо символов: `utf8.encode(_textController.text).length` (импорт `dart:convert`) — функция замыкание, видит `_textController`. Можно показывать `'$chars симв · $bytes Б'`.
- Анимация: вернуть `AnimatedOpacity`/`AnimatedSwitcher` — счётчик плавно появляется.
- Вместо текста — `Row` с иконкой `Icons.warning_amber` при `currentLength == maxLength`.

**7. Подводные камни.**
- `maxLength` в сигнатуре nullable — всегда проверяйте `null` или ставьте `!`, иначе analyzer ругается.
- Функция вызывается очень часто — не делайте в ней тяжёлого (сетевых запросов, больших вычислений); `utf8.encode` на 300 символах — нормально.
- Возврат `null` vs `SizedBox.shrink()`: `null` убирает слот, пустой виджет оставляет отступ — высота поля может «прыгать» при появлении счётчика. Если прыжок мешает — всегда возвращайте виджет, но с прозрачным текстом.
- Счётчик — часть `InputDecorator`, поэтому `decoration: InputDecoration(...)` с `isDense`/`contentPadding` влияет на его положение.

**8. Как проверить.** `flutter run -d linux`, правите функцию, нажимаете `r` (hot reload) — изменение видно сразу без перезапуска. Widget-тест: `await tester.enterText(find.byType(TextField), 'а' * 260); await tester.pump(); expect(find.text('260/300'), findsOneWidget);` — хороший первый тест, чтобы освоиться с `flutter test`.

Как реализовано выделение текста , который открывается по тапу на кнопке I?

*Devin* · 2026-10-06 17:49 UTC

Через стандартный виджет `SelectionArea` — <ref_snippet file="/home/ubuntu/repos/myself/flutter_color/lib/info_dialog.dart" lines="136-146" /> (одинаково во всех копиях).

Как устроено:
- Содержимое диалога `i` — обычные `Text` внутри `Column` → `SingleChildScrollView` → `Scrollbar`. Сами по себе `Text` не выделяются.
- Всё это обёрнуто в `SelectionArea`. Он делает выделяемыми **все** `Text`-потомки сразу (а не по одному, как `SelectableText`), причём выделение может идти через несколько абзацев. Внутри он ставит `SelectableRegion` с платформенными жестами: на телефоне — долгое нажатие, затем тянуть маркеры; на десктопе — мышью/двойным кликом/Ctrl+A.
- Контекстное меню («Копировать», «Выделить всё», на Android ещё «Поделиться») — системное, рисует его сам `SelectionArea` через `AdaptiveTextSelectionToolbar`; копирование идёт в буфер через `Clipboard.setData`. Своего кода для меню нет.
- Побочный эффект, отмеченный в комментарии: на десктопе перетаскивание мышью теперь выделяет, а не прокручивает; прокрутка — колесом, пальцем или ползунком `Scrollbar` (`thumbVisibility: true`, чтобы ползунок был виден всегда).
- Тест <ref_file file="/home/ubuntu/repos/myself/flutter_color/test/info_dialog_test.dart" /> перехватывает канал `Clipboard.setData`, выделяет текст в `SelectionArea` и проверяет, что в буфер ушёл текст.

Альтернативы, для сравнения: `SelectableText` — выделение в пределах одного виджета; свой `RichText` + `GestureDetector` — полный ручной контроль, но много кода. `SelectionArea` — самый дешёвый способ (одна строка-обёртка).
