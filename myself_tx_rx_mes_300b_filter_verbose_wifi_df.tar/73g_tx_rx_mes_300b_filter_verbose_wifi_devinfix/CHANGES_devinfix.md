`pubspec.yaml`, имя прошивки) оставлено прежним, чтобы сборка не ломалась.

## Прошивка

**A1. Таймаут ожидания конца передачи считается, а не задан константой.**
`TIMEOUT_MS 5000` был меньше блока (1480 бит / 300 бод = 4,93 с, с PTT ещё
+400 мс): `tx_ad9851_wait_idle()` отпускал мьютекс при работающем передатчике,
следующий блок молча портил текущий. Теперь в `afsk_common.h` есть
`BLOCK_BITS`/`BLOCK_AIR_MS`/`TX_IDLE_TIMEOUT_MS`, всё выводится из
`PREAMBLE_BITS`, `MAX_BLOCK_LEN`, `BAUD_RATE` и PTT-накладных.

**A2. `tx_idle_sem` осушается перед стартом.** Просроченный токен от прошлой
передачи заставлял `wait_idle()` вернуться сразу же.

**A3. Мьютекс отдаёт только владелец.** Вместо глобального `mutex_held`
владелец запоминается как `TaskHandle_t tx_owner`.

**A4. `_Static_assert` на GPIO < 32** в `tx_ad9851.h`: `set_frequency_fast()`
пишет только младшие `GPIO_OUT_W1TS/W1TC`, на пине ≥ 32 DDS молча не
тактировался бы.

**A5. Переполнение TX-кольца видно.** `afsk_serialize_block()` получил явные
аргументы `w_idx`/`r_idx`/`buffer_size` вместо скрытой глобальной `tx_bit_r_idx`
и возвращает число потерянных бит; на потерю пишется `ESP_LOGE`. Плюс
`_Static_assert` на то, что `TX_BIT_BUFFER_SIZE` вмещает блок.

**B1. `SIGNAL_TIMEOUT_MS` связан с паузой между блоками** через
`_Static_assert(BLOCK_GAP_MS + PTT_OVERHEAD_MS < SIGNAL_TIMEOUT_MS)`: иначе
приёмник рвал бы длинное сообщение на части.

**B3. Сброс состояния демодулятора один на все пути** (`reset_frame_state()`):
раньше по завершении кадра `prev_sign`/`have_prev_sign` не сбрасывались и
первый бит следующего кадра сравнивался со старым знаком.

**B5. Счётчики `start_dropout` и `start_wait`** больше не считаются через `||`
(короткое замыкание не давало расти второму).

**C1. WS-клиент регистрируется сразу после рукопожатия.** До этого слот
создавался только по `setName:`, и клиент, который его не присылает, обходил
ограничение частоты сообщений. Если слотов нет — кадр отклоняется, а не
пропускается.

**C2. POST длиннее буфера отклоняется** ответом `413 Payload Too Large`, а не
обрезается с ответом 200 OK.

**C3. Свободный слот помечается `-1`, а не `0`** (`WS_FD_NONE`): fd 0 —
допустимый дескриптор.

**C4. Пароль AP вынесен в `CONFIG_AFSK_AP_PASSWORD`** (`menuconfig` →
«AFSK Wi-Fi Access Point»). Значение по умолчанию совпадает с прежним
`"afsk12345"`, так что поведение не изменилось; копирование в
`wifi_config.ap.password` теперь через `strlcpy`.

**D1. `console_task` переехал на ядро 0** — на ядре 1 он мешал приёму.

**D2. Константы I2S-извлечения (`RX_DATA_BITS`, `RX_SLOT_BITS`,
`RX_SAMPLE_SHIFT`, `RX_SLOTS_PER_FRAME`) заданы один раз** и используются и в
конфигурации слота, и в разборе буфера: сдвиг на 8 и шаг 2 были магическими
числами.

**D3. Недостижимый код после бесконечных циклов** в `tx_task`/`rx_task` убран.

**A6. DPLL возвращён к формуле из git.** В присланном архиве (в git такого нет)
подстройка была переписана на `pll = sample_point + phase_err * PLL_INERTIA`,
то есть после перехода тон↔тон фаза притягивалась прямо к точке выборки и бит
читался в момент перехода, где согласованный фильтр ещё не устоялся. На вашем
же `hosttest/host_test.c` это давало 0/12 (ни один кадр не собирался), тогда
как закоммиченная версия даёт 12/12. Вернул `pll = pll * PLL_INERTIA` —
опорная точка на переходе это начало бита, а не `sample_point`.

**A7. Совместимость с вашим `hosttest` сохранена.** Пятиаргументный
`afsk_serialize_block()` остался (его вызывают host-тесты), а прошивка
использует новый `afsk_serialize_block_ring()` с `r_idx` и подсчётом потерь.

## Flutter

**E1. Соединение больше не рвётся из-за IP.** Признаком связи стал ответ платы
на `/ping` (`_pingEsp32()`), а не `192.168.4.*` от `network_info_plus`: на
десктопе и части Android плагин адрес подсети не отдаёт, и ручное подключение
сносилось поллингом через 5 с.

**E2. Ждём рукопожатие.** `await _webSocketChannel!.ready` вместо
`Future.delayed(500 ms)`, который успевал показать «Подключено» для соединения,
которое ещё могло не состояться.

**E3. Вытеснение из очереди эха идёт через `setState`** — галочка «отправляется»
висела до следующей перерисовки по другому поводу.

**E4. Пустой `setState` на каждом тике** (раз в 5 с) вызывается только при
фактической смене IP.

**E5. Тест соответствует приложению.** Шаблонный counter-тест (`flutter test`
был красный) удалён; разбор протокола вынесен в `lib/chat_protocol.dart` и
покрыт `test/chat_protocol_test.dart` — 7 тестов на `ping`, `System:`, деление
по первому двоеточию, ключ эха и длину кадра.

**E6. `connectivity_plus` удалён** из `pubspec.yaml` — он не использовался
(перерегистрация плагина в `GeneratedPluginRegistrant.java` обновлена).

**E8. Cleartext HTTP сужен до платы.** Вместо
`android:usesCleartextTraffic="true"` на весь трафик —
`res/xml/network_security_config.xml`, где HTTP без TLS разрешён только для
`192.168.4.1`.

**E11. Исключение `getWifiIP()` больше не отключает всю проверку связи.**
Нашлось при прогоне против заглушки: где `network_info_plus` бросает (десктоп
без NetworkManager, Android без разрешений), внешний `try` в `_checkConnection()`
перехватывал вызов до `_pingEsp32()`, так что автоподключение, автореконнект
и имя сети из `/info` не работали вообще. Адрес теперь берётся через
`_wifiIp()`, где исключение гасится локально.

**E9. Длина сообщения проверяется в байтах UTF-8** (`kMaxFrameBytes = 1024`,
как `WS_MAX_FRAME_LEN` в прошивке): 300 символов кириллицы — это 600 байт,
и вместе с `msg:<имя>:` лимит был близко.

## Что осталось нетронутым (по договорённости)

- **E7** — идентификатор кадра для сопоставления эха: меняет протокол, эхо
  по-прежнему сверяется по совпадению строк, поэтому два одинаковых текста
  подряд неразличимы.
- **E10** — распил `screen_pro.dart` (около 1000 строк) на транспорт, состояние
  и UI. Первый шаг сделан вынужденно: протокол уехал в `chat_protocol.dart`.
