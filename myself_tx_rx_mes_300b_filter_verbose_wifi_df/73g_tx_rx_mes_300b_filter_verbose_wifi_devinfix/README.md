# tx_rx_mes_300b_filter — AFSK-трансивер на одном ESP32 (300 бод, согласованный фильтр)

Объединение проектов `afsk_transmitter` и `decoder_afsk_rx_test` в один
ESP-IDF проект. **TX работает на ядре 0, RX — на ядре 1** (обе задачи
закреплены через `xTaskCreatePinnedToCore`).

Линк: Bell-202-подобный AFSK, **300 бод**, MARK 1200 Гц = «1», SPACE 2200 Гц = «0».
Кадр в стиле UART: преамбула (960 единиц, 3,2 с) → на каждый байт
`[START=0][8 бит LSB-first][STOP=1]` → байт CRC8 (poly 0x07) → хвост из единиц.

В демодуляторе однополюсный ФНЧ заменён на **согласованный фильтр** —
интегрирование I/Q-произведений ровно по длительности бита (см. ниже). Именно он
делает 300 бод рабочей скоростью: с прежним фильтром шумовой запас на 300 бод был
0,25, с согласованным — 0,65, то есть примерно как у 50–100 бод раньше.

Преамбула увеличена до 960 бит, чтобы её длительность осталась прежней (3,2 с) —
это время нужно сквелчу рации на открытие. Блок из 50 байт занимает ≈ 4,9 с
против ≈ 14 с на 100 бод.

> Проводной тест на реальном ESP32 пройден: сообщение 573 байта, 12 блоков,
> CRC OK на всех. В эфире (через рации) 300 бод ещё не подтверждены.

## Структура

```
main/
  main.c            app_main: NVS + TX init, затем tx_task (core0) и rx_task (core1)
  afsk_common.h     общие параметры линка (MARK/SPACE/BAUD/PREAMBLE/SAMPLE_RATE) + afsk_crc8
  afsk_protocol.*   сериализация кадра (TX) + единый CRC8
  tx_ad9851.*       драйвер DDS AD9851 (bit-bang) + GPTimer-ISR для битрейта
  afsk_decoder.*    демодулятор RX: квадратурный детектор + согласованный фильтр + DPLL
```

Разделение ядер:
- **Core 0 — TX**: `tx_task` читает строки из UART, режет на блоки ≤ 50 байт по
  границам символов UTF-8 (`afsk_utf8_block_len`) и передаёт через AD9851.
  Тайминг битов — аппаратный GPTimer-ISR.
- **Core 1 — RX**: `rx_task` инициализирует I2S-slave (48 кГц / 24 бит), читает
  сэмплы, прогоняет их через декодер и **склеивает принятые блоки в целое
  сообщение**.

### Склейка сообщения на приёме

Каждый принятый блок печатается как и раньше, а его полезная нагрузка (без CRC)
дописывается в буфер сборки. В протоколе нет маркера конца сообщения, поэтому
сообщение считается завершённым, когда следующий блок не приходит дольше, чем
длится передача одного блока: `MESSAGE_IDLE_MS` вычисляется из параметров линка
(преамбула + кадры данных и CRC + хвост + `BLOCK_GAP_MS`) с запасом 50 % — при
300 бод это ≈ 8 с. После этого печатается весь текст:

```
########################################
[RX] FULL MESSAGE: 200 bytes in 5 blocks
----------------------------------------
<полный текст>
########################################
```

Блоки с ошибкой CRC в склейку не попадают; их количество выводится отдельным
предупреждением, чтобы было видно, что текст неполный. Ограничение сборки —
`RX_ASSEMBLY_MAX` (8192 байт, как и буфер ввода TX).

GPIO не пересекаются: TX = 16/18/19/21, RX(I2S) = 22/25/26. Номера не зашиты в
коде, а объявлены в `main/Kconfig.projbuild` (меню «AFSK Pin Configuration») —
см. «Конфигурация выводов» ниже.

## Конфигурация выводов (Kconfig)

Все линии задаются символами `CONFIG_PIN_*`; значения по умолчанию — раскладка
WROOM, они же продублированы в `sdkconfig.defaults`. Под ESP32-S3-N16R8 лежит
отдельный набор `sdkconfig.defaults.esp32s3` (подхватывается автоматически при
`idf.py set-target esp32s3`), где переназначены линии, которых на S3 нет или
которые заняты:

| Линия | символ | WROOM | S3-N16R8 | причина замены |
|---|---|---|---|---|
| FQ_UD | `CONFIG_PIN_FQ_UD` | 18 | 18 | — |
| W_CLK | `CONFIG_PIN_W_CLK` | 19 | 4 | 19 = нативный USB на S3 |
| DATA | `CONFIG_PIN_DATA` | 21 | 21 | — |
| RESET | `CONFIG_PIN_RESET` | 16 | 16 | — |
| PTT | `CONFIG_PIN_PTT` | 17 | 17 | — |
| I2S BCK | `CONFIG_PIN_I2S_BCK` | 26 | 5 | 26 занят octal-PSRAM |
| I2S WS | `CONFIG_PIN_I2S_WS` | 25 | 6 | GPIO25 на S3 не существует |
| I2S DATA | `CONFIG_PIN_I2S_DATA` | 22 | 7 | GPIO22 на S3 не существует |

Пины S3 `4/5/6/7` — безопасный дефолт; на клонах N16R8 отдельные линии `1–18`
бывают заняты кнопками или светодиодами, поэтому перед прошивкой сверьтесь со
схемой платы. При конфликте меняется одна строка в
`sdkconfig.defaults.esp32s3`, код не трогается.

## HTTP API точки доступа

| запрос | ответ |
|---|---|
| `GET /ping` | `pong` (`text/plain`) — проверка доступности |
| `GET /info` | `{"ssid":"AFSK-TRX-XXXX","ip":"192.168.4.1"}` (`application/json`) |
| `POST /send` | `from=<имя>&text=<текст>` → блок уходит в очередь передачи |

`/info` отдаёт имя поднятой платой сети: приложению не нужно разрешение
геолокации, чтобы показать SSID (на Android `getWifiName()` требует
`ACCESS_FINE_LOCATION`).

## Демодулятор RX

1. **Квадратурный детектор тонов**: два NCO (mark/space) перемножаются с входным
   сигналом → четыре произведения (I и Q на каждый тон).
2. **Согласованный фильтр**: каждое произведение интегрируется ровно по одному
   биту (`MF_TAPS = SAMPLE_RATE / BAUD_RATE` отсчётов, скользящая сумма, O(1) на
   сэмпл). Для посылки «тон постоянной амплитуды длиной в бит» это оптимальный
   приём в белом шуме: нули АЧХ такого интегратора стоят кратно скорости, и при
   разносе тонов 1000 Гц чужой тон подавляется тем сильнее, чем точнее
   1000/BAUD — целое.
3. **DPLL**: аккумулятор битового такта переполняется раз в бит; каждая смена
   mark↔space подтягивает фазу, поэтому выборка остаётся в нужной точке бита
   даже при расхождении частот дискретизации TX/RX. Момент выборки сдвинут на
   `offset_frac = 0.10` относительно середины бита — компенсация задержки
   интегратора (у согласованного фильтра она ровно полбита от детектируемого
   перехода).
4. **Устойчивое обнаружение преамбулы**: детект по 3/4 длины преамбулы + допуск
   на «лишние» mark-биты на границе преамбула→START, чтобы дрейф не срывал кадр.

Стоимость: история фильтра — `MF_TAPS × 4` float в структуре декодера,
на 300 бод это 160 × 4 × 4 = **2,6 кБ** статической памяти (декодер объявлен
глобально, стек задачи не затрагивается). По CPU — 4 умножения и 8 сложений на
сэмпл, на 48 кГц незаметно.

## Порог по уровню (защита от ложной преамбулы)

Адаптивный порог считается от **слабейшего** из двух тонов, поэтому при
непрерывной паразитной несущей (собственный шум АЦП, наводка от тактов I2S,
незаглушённый передатчик) слабый тон исчезает, порог уползает вниз вслед за ним,
и приёмник видит бесконечную «преамбулу» на пустой линии — счётчик
`[PREAMBLE] .../720` крутится при conf 98–99 %, хотя ничего не передаётся.
На данные это не влияет (кадр не собирается, CRC не проходит), но ложный захват
может съесть начало настоящего блока.

Поэтому добавлены:

- **абсолютный порог** `MIN_TONE_AMPLITUDE` (по умолчанию 0,01 от полной шкалы,
  −40 дБ): всё, что тише, сигналом не считается никогда;
- **блокиратор постоянной составляющей** на входе (~10 Гц), чтобы смещение АЦП
  не подмешивалось в корреляторы;
- **измеритель уровня**: раз в 5 с на свободной линии печатается строка

  ```
  [LEVEL] peak: -62.0 dBFS | mark: -70.1 | space: -71.4 | squelch: -40.0 dBFS
  ```

  Настройка простая: уровень в паузе должен быть хотя бы на 10 дБ **ниже**
  squelch, а во время приёма — на 10 дБ **выше**. Если запаса нет, меняется одна
  константа `MIN_TONE_AMPLITUDE` в `main/afsk_decoder.c`
  (`LEVEL_REPORT_MS 0` выключает печать).

Всю диагностику (`[PREAMBLE]`, `[LEVEL]`, `[STAT]`) можно выключить одним
переключателем `AFSK_VERBOSE` в `main/afsk_common.h` (0 = тихий режим: в логе
остаются только принятые блоки и собранное сообщение).

Со стороны передатчика между блоками AD9851 теперь уводится в power-down
(бит W34 управляющего байта), а не просто настраивается на 0 Гц: работающий
ЦАП/компаратор продолжает подсвечивать аудиотракт и вход АЦП приёмника, и
именно это выглядит как паразитная несущая после передачи. Отключается
константой `TX_POWER_DOWN_WHEN_IDLE` в `main/tx_ad9851.c`.

Замер на host-стенде: с порогом −40 дБ паразитный тон 1200 Гц амплитудой 0,008
(−42 дБ) полностью игнорируется, а полезный сигнал принимается вплоть до
амплитуды 0,03 (−30 дБ). Печать прогресса преамбулы прорежена до 1/8 её длины.

Проверить это на своей сборке можно host-тестом простоя (`hosttest/idle.c`):

```
gcc -O2 -std=gnu11 -I hosttest/stubs -I 73g_tx_rx_mes_300b_filter_verbose_wifi/main \
    hosttest/idle.c 73g_tx_rx_mes_300b_filter_verbose_wifi/main/afsk_protocol.c \
    73g_tx_rx_mes_300b_filter_verbose_wifi/main/afsk_decoder.c -lm -o idle
./idle 0.02 15            # только шум: max_preamble_run=0
./idle 0.02 15 1200 0.008 # паразитный тон -42 дБ: тоже 0
./idle 0.02 15 1200 0.02  # тон -34 дБ: детект (порог пройден)
```

## Проверка (host-тесты)

DSP-часть проверена сборкой на хосте (`hosttest/`): TX-сериализация →
синтез тонов MARK/SPACE → декодер. Все кейсы проходят с проверкой полезной
нагрузки и CRC:

```
gcc -O2 -std=gnu11 -I hosttest/stubs -I 73g_tx_rx_mes_300b_filter_verbose_wifi/main \
    hosttest/host_test.c 73g_tx_rx_mes_300b_filter_verbose_wifi/main/afsk_protocol.c \
    73g_tx_rx_mes_300b_filter_verbose_wifi/main/afsk_decoder.c -lm -o ht
./ht        # 12/12 cases passed
```

Покрытие: nominal, дрейф ±0.3/0.6 %, шум, короткие/длинные посылки, а также три
многоблочных кейса (латиница, кириллица, эмодзи), где сообщение режется тем же
`afsk_utf8_block_len`, что и в прошивке, каждый блок проходит тракт целиком и
склейка сверяется с оригиналом побайтно.

Зона устойчивости по дрейфу тактовой (`hosttest/win.c`):
**[−1.9 % … +2.8 %]**. Реальный дрейф кварцев ESP32 (~±0.01 %) лежит внутри
с запасом ~100×.

Шумовой запас (амплитуда белого шума при амплитуде сигнала 0,30; порог — уровень,
на котором ещё ≥ 90 % из 20 посылок принимаются без ошибок):

| бод | однополюсный ФНЧ | согласованный фильтр |
|---|---|---|
| 50  | 0,85 | > 1,5 (граница не достигнута) |
| 100 | 0,65 | 1,10 |
| 300 | 0,25 | 0,65 |

## Работа через рации (PTT)

Ключевание передатчика рации **по умолчанию выключено**: в `main/tx_ad9851.h`
стоит `TX_PTT_ENABLE 0` — режим проводного стенда, поведение как в проверенной
по кабелю версии. Чтобы работать через рацию, поставьте в `main/tx_ad9851.h`
`#define TX_PTT_ENABLE 1` (значение в блоке `#ifndef TX_PTT_ENABLE`) и
пересоберите прошивку. Остальные настройки ключевания там же:

| параметр | значение | смысл |
|---|---|---|
| `PIN_PTT` | `CONFIG_PIN_PTT` (17) | выход на оптопару (PC817) вместо кнопки PTT |
| `PTT_ACTIVE_LEVEL` | `1` | уровень, при котором рация переходит на передачу |
| `PTT_LEAD_MS` | `300` | пауза после ключевания до первого бита преамбулы |
| `PTT_TAIL_MS` | `100` | удержание PTT после последнего бита |

Ключевание выполняется на каждый блок отдельно (а не на всё сообщение), чтобы не
упереться в таймер ограничения передачи (TOT) рации. Задержки автоматически
учитываются в тайм-ауте сборки сообщения на приёме.

Уровни аудио подбираются по строке `[LEVEL]` в verbose-сборке: в приёме
mark/space должны быть примерно −20…−10 dBFS, в паузе — заметно ниже
порога −40 dBFS.

> Примечание: полноценная сборка прошивки выполняется через ESP-IDF
> (`idf.py set-target esp32 && idf.py build`) — в этой среде тулчейн ESP-IDF не
> установлен, поэтому проверялась только переносимая DSP-логика. Хук `HOST_TUNE`
> в `afsk_decoder.c` компилируется только в host-тестах и полностью исчезает из
> прошивки ESP. Замеры сделаны на синтетическом белом шуме; в FM-эфире характер
> помех другой (пороговый эффект, импульсные щелчки), поэтому реальный выигрыш
> нужно подтверждать отдельно.
