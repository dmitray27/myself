# Радиочат УПТС-РК1 — версия PRO

Отдельная ветка продукта: прошивка `pro_version/firmware/` (ESP32 / ESP32-S3,
ESP-IDF 6.0.1) и приложение `pro_version/flutter_pro/` (Android, Linux).
Базовые версии (`../firmware`-часть в корне репозитория, `flutter/`, `flutter_info/`,
`flutter_firmware/`) не изменены. PRO-прошивка и PRO-приложение рассчитаны друг
на друга, но сохраняют совместимость с базовым протоколом: базовое приложение
работает с PRO-прошивкой (новые кадры оно не понимает и игнорирует), PRO-приложение
работает с базовой прошивкой (статусы дальше «принято УПТС-РК1» не появятся).

**Не проверено в эфире.** Обе части собраны и покрыты автотестами (см. ниже),
но с реальными радиостанциями и двумя платами не прогонялись. Перед
использованием нужен полевой тест: ACK, тайминги, занятый канал.

## Статусы сообщения — что они означают честно

| Статус | Иконка | Кто подтвердил | Смысл |
|--------|--------|----------------|-------|
| Отправляется на УПТС-РК1 | часы | никто | Кадр ушёл по Wi-Fi, эхо от платы ещё не пришло |
| Принято УПТС-РК1, ждёт эфира | песочные часы | своя плата (эхо WS) | Сообщение в очереди платы. **Это не доставка** |
| Передано в эфир, ждём подтверждения | одна галочка | своя плата (`status:aired`) | Все блоки переданы, ждём ACK до `ACK_TIMEOUT_MS` |
| Принято абонентом (XXXX) | две галочки | **удалённая станция** (`status:delivered`) | Получен ACK-кадр с ID станции XXXX |
| Нет подтверждения из эфира | перечёркнутое ухо | своя плата (`status:noack`) | Передали, ACK не пришёл. Может быть доставлено, а может нет |
| Не доставлено | ошибка | — | Отказ платы, обрыв связи, лимит попыток |

Правило приложения: «две галочки» появляются **только** после `status:delivered`
от прошивки, которое та шлёт **только** после валидного ACK из эфира. Эхо по
WebSocket, история `hist:` и повторный приём никогда не переводят сообщение в
«доставлено».

## Протокол ACK в эфире

Обычный блок: заголовок `seq, block_no, total` (3 байта) + до 50 байт текста +
CRC. ACK — кадр той же физической рамки длиной ровно `AFSK_ACK_FRAME_LEN` = 7 байт:

```
[0] seq   — seq подтверждаемого сообщения
[1] 1     — AFSK_CTRL_ACK
[2] 0
[3..6]    — ID станции, 4 hex-символа (младшие 2 байта Wi-Fi MAC платы)
```

Плата, полностью собравшая чужое сообщение (все блоки, CRC верна), через
`ACK_DELAY_MS` (400 мс) передаёт ACK. Передающая плата после последнего блока
ждёт `ACK_TIMEOUT_MS` (≈ 2·(400 + PTT + время ACK в эфире) + 1000 мс):
ACK с нужным `seq` → `delivered`, иначе → `noack`. ACK-кадры распознаются
до разбора текста, в чат не попадают, на ACK не отвечают ACK'ом. Повторные ACK
на уже закрытый `seq` учитываются только как «станция в эфире».

Ограничение: подтверждение шлёт **каждая** принявшая плата, ACK разных станций
могут наложиться в эфире — тогда ни один не декодируется и отправитель получит
`noack`, хотя сообщение доставлено. При группе >2 станций «нет подтверждения»
надо трактовать как «неизвестно», а не «не дошло».

## Автоповтор (приложение)

`ChatController(maxAttempts: 3, retryBackoff: 5 с)`. Повтор планируется:

- при `noack` или `failed`;
- при обрыве Wi-Fi/WS — все сообщения без эха возвращаются в «отправляется»;
- если эхо не пришло за `echoTimeout` (6 с).

Попытка N ждёт `retryBackoff · N`. Сообщения в состоянии «принято»/«в эфире»
не повторяются (плата их уже обрабатывает). После `maxAttempts` — «не доставлено»;
долгое нажатие на сообщение → «Повторить» (сбрасывает счётчик). Повтор идёт с
тем же `id`, поэтому получатель отбросит дубликат.

## Статистика канала

Прошивка ведёт `link_stats_t` и раз в `STATS_PUSH_MS` (2 с) рассылает кадр
`stat:{...}` всем WS-клиентам (только если что-то изменилось); то же по `GET /stat`:

```json
{"rx":12,"crc":1,"abort":0,"msgs":5,"incomplete":0,"tx":4,"acked":3,"noack":1,
 "rx_busy":false,"tx_busy":false,"signal_db":-9,"preamble":97,"station":"8045"}
```

`rx` — принятых кадров, `crc` — с ошибкой CRC, `abort` — прерванных, `msgs` /
`incomplete` — собранных / брошенных сообщений, `tx`/`acked`/`noack` — своих
сообщений, `rx_busy`/`tx_busy` — эфир занят приёмом / передачей, `signal_db` —
уровень входа относительно полной шкалы, `preamble` — % корректных бит преамбулы
в последнем кадре, `station` — ID своей платы.

Приложение показывает строку под AppBar («Эфир: свободен • сигнал −9 дБ •
преамбула 97 % • CRC 1»), полную таблицу — по иконке статистики.

## Абоненты в эфире (10б)

Каждый валидный ACK обновляет запись `станция → время` (до `PEERS_MAX` = 8,
TTL `PEER_TTL_S` = 900 с). Плата шлёт `peers:8045=12,1A2B=340` при подключении
клиента и при каждом изменении. Приложение показывает счётчик в строке канала и
список с возрастом в диалоге статистики. Абонент в списке означает «от него
слышали ACK не позже 15 мин назад», не «он сейчас на связи».

Занятость имени: `setName:<имя>` отвергается, если это имя уже у другого живого
WS-клиента этой платы → `System:name busy`; успех → `System:name ok`. Приложение
при `name busy` возвращает прежнее имя и просит выбрать другое. Служебные
имена `status`, `stat`, `peers`, `hist`, `ping`, `pong` запрещены на плате и в
приложении, чтобы чат-кадр нельзя было спутать со служебным.

## История и экспорт (4)

Сообщения (до 500) хранятся в `shared_preferences` (`history_v1`, JSON) и
восстанавливаются при запуске; сообщения, не дошедшие до финального статуса,
после перезапуска отмечаются «не доставлено» (ACK на них уже не придёт).
Настройки → История: очистить; скопировать текст; сохранить `.txt`
(`radiochat-YYYYMMDD-HHMMSS.txt` в «Загрузки» на Android, в документы
приложения на Linux). Формат строки: `[2026-01-02 03:04:05] Имя: текст — доставлено (8045)`.

## Полевой режим (6)

Настройки → «Полевой режим»: принудительно тёмная тема, шрифт сообщений и поля
ввода крупнее, кнопка отправки и иконки статуса увеличены. В ландшафте пузыри
ограничены по ширине, чтобы строки не растягивались на весь экран.

## Шифрование (7)

`lib/group_cipher.dart`: AES-256-GCM, ключ = SHA-256(парольная фраза группы),
случайный nonce 12 байт, тег 16 байт. В эфир уходит

```
#e1.<base64url(nonce || ciphertext || tag)>
```

Префикс без `:` не ломает разбор `<имя>:<id>:<текст>`; прошивка ничего о
шифровании не знает. Имя отправителя и `id` **не шифруются**. Накладные расходы —
28 байт + base64 (≈ ⁴⁄₃), приложение проверяет размер зашифрованного кадра до
отправки. Без ключа или с другим ключом текст показывается как
«[зашифровано: ключ не совпадает]» (курсивом). Ключ хранится в `shared_preferences`
телефона; отпечаток ключа (4 hex) виден в строке канала для сверки голосом.
Пустой ключ = открытый текст. Это защита от чтения посторонним с таким же
комплектом; от подмены/повтора отправителя (имя открыто) не защищает.

## Настройка точки доступа (8)

Прошивка хранит SSID/пароль в NVS (namespace `afsk`, ключи `ssid`, `pass`).

- `GET /config` → `{"ssid":"AFSK-TRX-8045","custom":false}` — пароль не отдаётся.
- `POST /config` с `ssid=...&pass=...` (SSID 1–32 байта без `"`, пароль 8–63 ASCII)
  или `reset=1` (вернуть заводские `AFSK-TRX-xxxx` / `afsk12345`). Ответ `ok`,
  плата перезагружается через ~1 с. Пароль в лог не пишется.

Приложение: Настройки → Точка доступа. После применения телефон надо вручную
подключить к новой сети (10а не делалось).

## Контракт HTTP/WebSocket (полный)

Wi-Fi AP `AFSK-TRX-xxxx`, шлюз `192.168.4.1`, HTTP :80, WebSocket :81 путь `/`.

HTTP: `GET /ping`, `GET /info`, `POST /send` — как в базовой; новые `GET /stat`,
`GET /config`, `POST /config`.

WS клиент → плата (без изменений): `setName:<имя>`, `msg:<имя>:<id>:<текст>`,
`msg:<имя>:<текст>` (legacy), `ping`.

WS плата → клиент: базовые `<from>:<id>:<text>`, `<from>:<text>`, `hist:...`,
`System:<текст>`, `pong`; новые:

```
status:<id>:accepted|aired|delivered|noack|failed[:<деталь>]
stat:{...json...}
peers:<станция>=<сек>,...
System:name busy
System:name ok
```

Лимиты (`afsk_common.h`, `wifi_link.c`): имя ≤ 31 байт, кадр ≤ 1024 байт,
текст ≤ 50·255 байт, ≥100 мс между `setName:` и первым `msg:`. При изменении
констант в прошивке править `chat_protocol.dart` (тесты зеркалят лимиты).

## Сборка и тесты

Прошивка:

```bash
. $IDF_PATH/export.sh            # ESP-IDF 6.0.1
cd pro_version/firmware
idf.py set-target esp32          # или esp32s3 (SDKCONFIG_DEFAULTS=sdkconfig.defaults.esp32s3)
idf.py build flash monitor
```

Приложение:

```bash
cd pro_version/flutter_pro
flutter pub get
flutter analyze
flutter test                     # 60 тестов: протокол, статусы, повтор, история, шифрование
flutter build apk
```

Тесты `test/`: `chat_protocol_test.dart` (кадры `status`/`stat`/`peers`,
служебные имена, лимиты AP), `message_store_test.dart` (эхо ≠ доставка,
переходы статусов, повтор, персистентность), `group_cipher_test.dart`,
`history_store_test.dart`.

## Известные ограничения

- Нет полевой проверки: тайминги ACK/таймаутов рассчитаны, не измерены.
- Коллизии ACK при >2 станциях → ложный `noack` (см. выше).
- Статистика пишется из задач RX/TX без блокировок — отдельные счётчики могут
  на мгновение расходиться, для индикатора это допустимо.
- Шифрование не скрывает имя и `id`, не защищает от повтора кадра.
- Ключ группы и история хранятся на телефоне в открытом виде (`shared_preferences`).
- После смены SSID приложение не переподключает Wi-Fi само.
